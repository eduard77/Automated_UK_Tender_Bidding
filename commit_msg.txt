fix(discovery): make CF/FTS backlog catch-up resumable — persist resume watermark incrementally, survive 900s-timeout cancellation

VERDICT: the CF/FTS 900s non-advancing loop is fixed. Progress wasn't
persisting on timeout because the 900s self-heal is an asyncio.wait_for that
cancels the poll task with a CancelledError — a BaseException that bypasses
poll_source's `except Exception` AND its end-of-run watermark-persistence/commit
(the #131 incremental watermark only ran on a graceful finish, never on a
cancellation). Records were committed per-record but source.last_polled_at was
only advanced at the END, which the cancel skipped — so every cycle re-fetched
the same 12-day backlog, timed out, discarded the watermark, and looped.

Fix — persist the resume point INCREMENTALLY so a cancel can't discard it:
- poll_source advances + COMMITS the resume watermark (and run.fetched /
  run.watermark_at) the moment each page confirms, inside the loop. A
  cancellation lands during the adapter's next HTTP await, AFTER the last
  page's progress is durably committed, so a cancelled mid-sweep run keeps
  everything fetched and the next run resumes from there. Monotonic; strict
  forward progress via the existing confirm-then-advance tracker (a
  descending/unordered feed still never advances → no unfetched page skipped).
- Verified for CF (HTTP date watermark) AND FTS, including FTS's page-14
  salvage-and-continue: salvaged records commit and the resume point advances
  past the bad page before the sweep continues, so a later timeout resumes
  after it, never before.
- The 900s timeout self-heal is UNTOUCHED — not raised; resumability is the
  correct fix (backlog can always exceed any fixed window).

Diagnosis clarity:
- poll_runs.watermark_at (additive, nullable — migration 0019) records the
  resume point each run reached.
- sources-health gains `catching_up`: a run that errored/timed-out but whose
  watermark ADVANCED past the previous run's is a converging backlog drain, not
  a fault — distinct from `fetch_failing` (errored AND no forward progress:
  same watermark run-to-run, or none). Based on watermark movement, not run
  status. The per-run watermark_at is surfaced so the operator can watch it
  climb to present (then runs complete ok).

Out of scope, unchanged: NI (500) / S2W (cert) contained upstream outages;
Proactis manual_browser_discovery; classification.
